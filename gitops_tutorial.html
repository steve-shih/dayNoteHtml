從零開始掌握 GitOps、ArgoCD 與 GCS 完美備援

🧭 什麼是 GitOps？

傳統的部署是人手動把程式碼推上伺服器。但在 GitOps 的世界裡，「Git 倉庫就是唯一的真理」。

我們將職責一分為二：

  • 應用程式倉庫 (dayNoteApp)： 負責寫程式。當您推送程式碼，GitHub Actions 只負責把它打包成 Docker 映像檔。
  • 基礎設施倉庫 (k8s-infra)： 負責寫架構。這裡面只有 YAML 設定檔。

ArgoCD 就像是一個有強迫症的糾察隊。它住在您的 Kubernetes 叢集裡，每天死死盯著 k8s-infra 倉庫。只要倉庫裡的 YAML 檔一有風吹草動，它就會立刻把線上系統修改成跟 YAML 一模一樣的狀態！

🚀 我們打造的全自動流水線 (做法二)

剛剛我們將您的系統升級到了「最高等級」的 CI/CD 連動法。當您未來開發完新功能並 git push 後，會發生這場魔法：

  • 自動編譯： GitHub Actions 幫您編譯出帶有最新 Git 版本號 (SHA) 的 Docker 映像檔。
  • 自動連動： GitHub Actions 拿著秘密鑰匙 (INFRA_PAT)，偷偷跑到您的 k8s-infra 倉庫，幫您把 k8s-prod.yaml 裡面的版本號改成最新的。
  • ArgoCD 發威： ArgoCD 發現 k8s-infra 變了！它立刻發動，在線上叢集為您無縫抽換最新的容器！
⚠️ 必做的設定：INFRA_PAT

為了讓這個魔法生效，您必須去 GitHub 產生一把具有 repo 權限的 PAT (Personal Access Token)，並將它存入 dayNoteApp 的 Repository Secrets 中，命名為 INFRA_PAT。

☁️ GCS 與 A ∪ B 完美備援機制

我們也成功解決了「檔案遺失與不一致」的問題，現在您的系統固若金湯：

1. 備援機制： 當使用者上傳檔案時，系統會優先傳到 GCP 雲端 (Bucket: petpa)。如果雲端突然壞了，系統會「備援」將檔案暫存在本地容器中，確保使用者的操作不中斷。

2. A ∪ B 自動大掃除： 我們在背景植入了 APScheduler。每個月的 1 號凌晨 3 點，系統會自動甦醒，將掉落在本地的暫存檔全部補推上 GCS，並確保本地與 Atlas 資料庫的狀態達成 完美的聯集 (A ∪ B)。

3. K8s 機密掛載： 您的 GCP 金鑰現在被安全地鎖在 Kubernetes 的 Secrets 中，並動態掛載給容器，GitHub 上絕對看不到您的密碼！

🔐 如何登入觀看您的線上 ArgoCD？

因為資安考量，ArgoCD 預設是不公開的。當您想看它時，請打開終端機，執行以下「打洞」指令：

# 1. 切換到 GCP 雲端叢集
gcloud container clusters get-credentials steve-k8s-cluster --zone asia-east1-a --project qqcat-454915

# 2. 開啟私密隧道
kubectl port-forward svc/argocd-server -n argocd 8081:443

接著打開瀏覽器前往：https://localhost:8081
