四、經典觀念與面試回答

問題回答重點漂亮講法
100 萬會員要開幾台？ 不能只看會員數，要換算 DAU、CCU、QPS。 我會先推估日活與尖峰 QPS，再用壓測結果決定機器數，正式環境至少兩台避免單點故障。
CPU 只有 30%，為什麼還是慢？ 可能是 DB、IO、Network、Lock、外部 API、Memory 不足。 CPU 不高代表瓶頸不一定在運算，我會看 DB explain、慢查詢、連線池、磁碟 IO、網路延遲與錯誤率。
什麼時候加 Redis？ 熱門資料重複查、DB 壓力大、讀多寫少。 如果同一批資料被大量重複讀取，我會先加 Cache，而不是盲目加 DB 規格。
什麼時候加 Queue？ 非即時任務、尖峰流量、報表、寄信、批次處理。 Queue 的價值是削峰填谷，讓系統先接住請求，再由 Worker 慢慢處理。
什麼時候用 GKE？ 服務多、部署頻繁、自動擴縮、需要容器編排。 小系統 VM 就夠，大到服務很多、需要自動部署與擴縮時，才導入 Kubernetes / GKE。
