User / Browser

定位
請求來源，也是體驗最終反映點。
層級 / 協定
L7 Application；HTTP / HTTPS。
為何這樣做
  • 所有架構最終都服務使用者。
  • 排查故障時，先確認是單一使用者、單一地區，還是全體異常。
可以幹嘛
  • 發送網頁請求。
  • 發送 API request。
  • 用 DevTools 看 DNS、TLS、TTFB、下載時間。
流量與規模差異
  • 小型：直接進 Nginx。
  • 中型：先進 LB，再進 VM。
  • 大型：先經 CDN / WAF / LB。
  • 超大型：先被 Global DNS 導到某個 Region。
資安重點
  • Cookie、JWT、CORS、CSRF 都會與瀏覽器相關。
故障排除重點
  • 看瀏覽器 Network。
  • 確認是否只有特定地區慢。
  • 確認是否為前端快取或 Cookie 問題。

架構演化重點表

規模 入口層 運算層 Cache / Queue DB Cluster / Replica 流量處理 故障排除主軸
小型 DNS → Nginx 單台 VM + PM2 / Docker 通常沒有，或單一 Redis 單機 DB + Backup Nginx 做基本反向代理與限流 DNS、Nginx、App Log、DB slow query
中型 DNS → Cloud LB → Nginx MIG / VM Group / 多台 App Redis Cache、簡單 Queue、Worker Primary + Secondary + Read Replica + Backup LB 分 VM；Nginx 分 API；Redis 擋 DB；Queue 削峰 LB Health、VM 飽和、Nginx 502、App latency、Replica lag
大型 / 中大型 DNS → CDN → WAF → LB → Ingress K8S Cluster、多服務、多 Pod、HPA Redis Cluster、Kafka/RabbitMQ、Worker Pool DB Cluster、Replica Set、Shard、Data Warehouse、CDC CDN 吃靜態；WAF 擋攻擊；K8S 擴容；DB 分讀寫 Golden Signals、Trace、Queue Lag、Cache Hit、DB Explain
超大型 Global DNS → Multi CDN/WAF → Regional LB Multi Region K8S / Service Mesh Regional Redis Cluster、Global Event Stream Multi-Region DB、Shard by region/tenant、Cross-region replica 依國家/延遲/健康度導流；區域故障切換 先判斷全球或單區，再查跨區同步、DNS、Region Health
