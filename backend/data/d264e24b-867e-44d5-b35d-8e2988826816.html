Mac + Windows Homelab：OpenStack / Kubernetes / DevOps 全景架構圖

這份圖用「不同角度」拆解兩台電腦如何組成一個實驗室：從實體設備、網路切割、OpenStack、Kubernetes、CI/CD、監控、Log、儲存，到使用者請求如何一路進入服務。

適合：OpenStack / K8s / DevOps / SRE 練習 設備：Mac + Windows 核心：兩台電腦先用 VM 模擬企業架構

總覽圖：兩台電腦組成一個小型雲端實驗室

核心概念：Mac 和 Windows 不直接跑 OpenStack，而是各自透過虛擬化軟體建立 Ubuntu VM，再用這些 VM 組成 OpenStack、K8s、監控與 CI/CD 環境。

主軸OpenStack 負責練 IaaS，也就是像雲端平台一樣開 VM、建網路、掛 Volume。
主軸Kubernetes 負責練容器平台，把服務包成 Pod，做滾動更新、Service Discovery、Ingress。
主軸CI/CD 負責從 Git Push 到自動測試、建 Docker Image、部署到 K8s。
主軸Monitoring / Logging 負責觀察系統 CPU、Memory、Disk、API Error、Pod Restart、OpenStack 服務狀態。
建議先把目標定為「可操作、可展示、可寫進履歷」的 Lab，不要一開始追求正式 HA。兩台電腦足夠練完整流程，但不適合真的承載正式業務。

角度一：實體與虛擬化層

這一層回答：Mac 和 Windows 要怎麼變成可用的 Linux 節點。

MacHost OS：macOS
Windows PCHost OS：Windows
↓
UTM / VMware Fusion建立 Ubuntu VM
VMware Workstation / Hyper-V建立 Ubuntu VM
↓
Ubuntu VM AController / Monitoring
Ubuntu VM BCompute / K8s Worker
Ubuntu VM CGitLab / Registry
Host OS：你的原本系統。Mac 是 macOS，Windows 是 Windows。它們主要負責提供 CPU、RAM、Disk、Network。
Hypervisor：虛擬化軟體，例如 VMware、UTM、Hyper-V。它負責在實體電腦裡切出多台 VM。
Ubuntu VM：真正執行 OpenStack / K8s 的環境。因為 OpenStack 主要跑在 Linux 上，所以 VM 裡建議用 Ubuntu Server。
Nested Virtualization：如果你想在 VM 裡再開 OpenStack VM，需要開啟巢狀虛擬化。Windows PC 通常比 Apple Silicon Mac 更適合。

角度二：網路與 IP 規劃

網路不要全部混在一起。即使是 Lab，也建議用不同網段模擬企業環境。

Router192.168.1.1 / Internet Gateway
↓
Management10.0.10.0/24
Storage10.0.20.0/24
Kubernetes10.0.30.0/24
Monitoring10.0.40.0/24
External10.0.50.0/24
網段用途為什麼要分開範例
Management Network管理節點之間通訊OpenStack API、SSH、內部服務不應跟使用者流量混在一起10.0.10.11 Controller、10.0.10.21 Compute
Storage NetworkVolume、Image、備份資料流磁碟流量大，會影響 API 與服務流量10.0.20.0/24
Kubernetes NetworkPod、Service、Node 通訊K8s 有自己的容器網路與 Service 網路10.0.30.0/24
Monitoring NetworkPrometheus 抓指標避免監控流量干擾正式服務，也方便限制權限10.0.40.0/24
External Network對外入口、Floating IP、Ingress使用者進來的流量需要獨立控管10.0.50.0/24
如果只是第一次練，可以先全部用同一個 192.168.1.0/24。但第二階段要開始切 Management / External，否則 OpenStack Neutron 觀念會很難真正理解。

角度三：OpenStack 私有雲

OpenStack 是 IaaS 平台，重點是讓你像用 AWS EC2 一樣，自己建立 VM、網路、磁碟與映像檔。

Neutron虛擬網路 / Router / Security Group

↓

VM InstancesUbuntu VM / Rocky VM / App VM
Keystone：管理帳號、Token、Project、Role。你可以練「誰可以開 VM、誰可以看資源」。
Nova：負責 VM 生命週期，例如建立、關機、重開、刪除、Resize。
Neutron：最重要也最難。它負責虛擬網路、Router、Floating IP、Security Group。
Glance：存放 VM Image，例如 Ubuntu Cloud Image。Nova 建 VM 時會從這裡拿 Image。
Cinder：提供可掛載到 VM 的 Block Storage，像雲端硬碟。
RabbitMQ / MariaDB：OpenStack 控制平面的核心依賴。RabbitMQ 傳遞任務，MariaDB 保存狀態。

角度四：Kubernetes 容器平台

K8s 是跑應用程式的容器平台。OpenStack 偏「開 VM」，K8s 偏「跑服務」。

↓

Pod最小運行單位
ConfigMap / Secret設定與機密
API Server：所有操作都先打到這裡，例如 kubectl apply、CI/CD 部署。
Scheduler：決定 Pod 要放在哪個 Worker，會考慮 CPU、Memory、Taint、Affinity。
Deployment：描述服務要跑幾份、用哪個 Image、如何更新。
Service：Pod IP 會變，Service 提供穩定入口。
Ingress：HTTP/HTTPS 入口，例如 app.local、grafana.local。
ConfigMap / Secret：把設定與密碼從程式碼中拆出來，方便環境切換。

角度六：監控與告警

監控不是只看 CPU，而是要回答「系統是否健康、問題在哪一層、是否會影響使用者」。

Node Exporter主機 CPU / RAM / Disk
cAdvisorContainer 指標
kube-state-metricsK8s 物件狀態
OpenStack ExporterOpenStack 服務狀態
↓ scrape
Prometheus時間序列資料庫與查詢
↓ query / alert
GrafanaDashboard
AlertManagerEmail / Teams / Slack 告警
指標代表意義常見判斷
CPU Usage運算資源是否吃滿長期超過 80% 要看是否需要擴容或限制服務
Memory Usage是否有記憶體壓力接近滿載、頻繁 OOMKilled，代表服務設定或資源不足
Disk IO / Disk Usage磁碟容量與讀寫瓶頸磁碟超過 80% 要預警；IO Wait 高會拖慢整機
Pod Restart Count容器是否反覆重啟短時間大量增加，多半是程式錯誤、設定錯誤或資源不足
API Latency使用者感受到的速度P95 / P99 延遲比平均值更重要
HTTP 5xx Rate服務錯誤比例突然上升要立刻查 Log 與近期部署

角度七：Log 與問題追蹤

Log 是排查問題的證據鏈。監控告訴你「有問題」，Log 告訴你「問題發生在哪裡」。

App LogAPI / Error / Business Log
Nginx LogAccess / Error
K8s LogPod / Event
OpenStack LogNova / Neutron / Keystone
↓ collect
Filebeat / Fluent Bit收集與轉送 Log
↓ parse
Logstash / Pipeline格式化、切欄位、清洗
↓ store
Elasticsearch / OpenSearch儲存與搜尋
↓ visualize
Kibana / Dashboard查詢錯誤、追 Trace ID
Access Log：看誰打了哪個 API、狀態碼、耗時、來源 IP。
Error Log：看程式錯誤、例外堆疊、資料庫錯誤。
Trace ID：一次請求一路從 Nginx、API、DB 都帶同一個 ID，方便串起完整路徑。
Retention：Log 不能無限存，Lab 可設定 7～14 天，避免磁碟爆掉。

角度八：儲存與備份

兩台電腦可以練儲存概念，但不適合正式 Ceph 高可用。Ceph 正式環境通常至少三台以上較合理。

Local DiskVM Disk / Host Disk
Cinder VolumeOpenStack Block Storage
NFSLab 共用儲存
Ceph Lab只建議練概念
↓ backup
Snapshot快速還原點
External Disk離線備份
Cloud Backup重要設定檔備份
儲存類型適合用途風險
Local Disk最簡單，適合 VM、Lab、測試服務主機壞掉資料可能一起消失
NFS簡單共享檔案、K8s 測試 PV單點故障，效能普通
Cinder練 OpenStack Volume 掛載背後仍要有穩定儲存
Ceph練分散式儲存、RBD、OSD、Monitor兩台不適合正式 HA，硬體資源吃重
Snapshot升級前、實驗前保護環境不能取代真正備份

Nginx / HAProxy：入口層，負責把不同網域或路徑導到不同服務。
K8s Ingress：容器平台內的 HTTP 路由，常見搭配 Nginx Ingress Controller。

學習順序與實作路線

不要一次全部裝，會很容易卡住。建議用階段式完成，每一階段都要能驗收。

階段目標驗收方式
STEP_01兩台電腦互通，VM 可 SSHMac VM ping Windows VM；Windows VM ssh 到 Mac VM
STEP_02建立基礎 Linux Lab所有 VM 固定 IP、可互相解析 Hostname
STEP_03先完成 Kubernetes部署一個 Node.js API，透過 Ingress 打得到
STEP_04加入 CI/CDGit Push 後自動 Build Image 並部署到 K8s
STEP_05加入監控Grafana 看得到 Node、Pod、API 指標
STEP_06加入 LoggingKibana / OpenSearch 查得到 API Error Log
STEP_07再做 OpenStackHorizon 可登入，能開 VM、建 Network、綁 Floating IP
STEP_08整合 OpenStack + K8sOpenStack VM 裡也能加入 K8s Worker 或跑服務
履歷可以寫成：自建 Homelab，包含 Linux VM、Kubernetes、OpenStack、CI/CD、Prometheus/Grafana、集中式 Log，並具備網路切割、資源監控與服務部署經驗。
